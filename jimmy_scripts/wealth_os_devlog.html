2026-10-08　排程改由本機 launchd 觸發：先證明「不是我們的錯」，再換掉觸發源

需求：Jimmy 問「這次排程怎麼延遲這麼久？跟處理的事情份量有關係嗎」。 當天（10/05）排程遲到 8h35m，而那次剛好是投資日誌重建上線後第一次跑、工作量變大， 直覺上很容易歸因到「事情變多所以跑比較久」。

實作：用 GitHub API 把一次執行拆成三段時間來看—— created_at（GitHub 決定建立這次執行）、run_started_at（runner 接手）、 updated_at（跑完）。近 11 次的結果：排隊一律 0 分、實際執行只 0.4~4.5 分、 但「建立執行」遲到 5h08m~8h35m。決定性的一筆是 09/28——守衛判定非交易日、整個 job 只跑 0.7 分鐘，照樣遲到 7h47m。工作量與遲到幅度毫無相關性，瓶頸完全在 GitHub 的 cron 派發。 確認後改由本機 launchd（com.jimmy.wealthsync，每天 14:30）打 API 觸發 workflow_dispatch（實測秒級啟動），GitHub cron 保留當備援。

踩坑與解法：

  • 先改 cron 時段是無效的猜測，而且害了一天。第一步只把 cron 從 :30 改成 :17（想避開整點／半點擁塞）。結果隔天（10/06）排程整次被丟掉，當天的國泰漲跌／ 除息日曆／跌幅查詢頁／加碼損益全缺，需人工補跑；10/07 又遲到 7h04m。 改 cron 沒有改善，而且 10/06 很可能是改動造成的一次性副作用。 教訓：在沒有機制性證據前就動設定，等於拿正式排程做實驗。
  • launchd 讀不到 ~/Downloads——macOS TCC。plist 一開始直接指向 jimmy_scripts/trigger_wealth_sync.sh，launchd 回 /bin/bash: …: Operation not permitted。launchd 叫起的程序沒有完全取用磁碟權限， 專案整個放在 ~/Downloads 底下就全都讀不到——不只腳本，連 import twse_hist、 source _load_pat.sh 也一樣。解法：腳本改成完全自足（內建 TWSE 交易日判斷含主／備端點 fallback、自行讀 PAT），安裝到 ~/Library/Application Support/wealth-sync/； jimmy_scripts/ 的那份降為版控母本，改完要重跑安裝指令。
  • 手動觸發一律被守衛放行，週末會重跑前一個交易日。workflow 的「交易日守衛」是 run = manual or (target == t)——workflow_dispatch 的 manual 永遠為真。 週末照打的話它會拿「最近一個有收盤資料的交易日」再跑一次，覆寫 runlog 並多推一則 LINE。 所以觸發腳本必須自己判斷交易日，另加「今天已有成功執行就不重複觸發」的保護。
  • 「讓它自己補漏跑的日子」這個提議是錯的，查了才發現做不到。原本打算讓腳本偵測到漏跑就自動補， 實查 workflow 才發現 workflow_dispatch 只有 job 一個 input、守衛固定用 datetime.date.today()，觸發永遠只能處理今天。 （10/07 00:11 那次能補到 10/06，是因為當時 TWSE 還沒有 10/07 資料、守衛才算出 10/06—— 時間湊巧，不是可重複的機制，我一度把它當成機制來推論。） 要能指定日期得先給 workflow 加 target_date，而且「更新股價」的快照滾動 假設日期往前推進，倒著建快照會讓分頁順序與 H~K 欄錯亂。 故降級為只偵測警示、不自動補：每次執行比對「最近 5 個交易日」與線上 runlog.json。
  • TWSE 收盤資料不保證 14:30 就上架。原本的 cron 因為永遠遲到數小時，從來沒驗證過這件事。 launchd 準時跑就會碰到，故腳本在判定非交易日前重試 6 次 × 10 分鐘（等到約 15:30）。

驗證結果：shell 語法、plist plutil -lint、模式字串與 workflow choice 選項逐字比對 （全形＋）皆通過；四條分支實測正確（非交易日安靜結束、--now --dry-run 正常載入 PAT、 未知參數 exit 2、launchd 實際叫起腳本後 stderr 為空）。 重複保護以真實 runlog 驗證：模擬「今天是 10/07」→ 找到成功執行、不觸發；「今天是 10/06」→ 會觸發。 漏跑偵測同樣以真實資料驗證不是空轉：現況回報「最近 5 個交易日都有成功紀錄」， 模擬 runlog 缺 10/06 時正確抓出該日。 尚未驗證的是「交易日當天準時觸發」這條路徑——安裝時是凌晨、當天尚未開盤， 已排定 14:50 自動檢查回報。另確認 Mac 接電源時 pmset sleep=0（永不睡眠）， 僅電池模式為 1 分鐘，故只需保持插電。

2026-10-08　投資日誌重建機制首次實戰：穎崴零股買進，重複補登沒有發生
